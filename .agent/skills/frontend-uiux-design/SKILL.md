# Frontend UI/UX Design Skill

## Purpose

Help design practical, visually polished, accessible, and responsive web application interfaces.

Use this skill when asked to:
- Design a new web application interface.
- Plan screens, layouts, and user flows.
- Create or review a design system.
- Evaluate a Figma design.
- Prepare UI specifications for frontend implementation.

## Workflow

### 1. Understand the project

Read available project context, including:
- Product intent
- Approved specifications
- Existing UI requirements
- User workflows
- Existing design references

Identify the target users and primary actions.

Do not invent product features or change approved requirements.

### 2. Define the UI structure

Identify:
- Required screens
- Navigation structure
- Main user flows
- Reusable components
- Important UI states

Keep the MVP scope small.

### 3. Establish a design system

Recommend:
- Color palette with accessible contrast
- Typography and hierarchy
- Spacing scale
- Border radius and shadows
- Buttons, inputs, and cards
- Icons and visual consistency

Prefer a simple, reusable system.

### 4. Design responsive layouts

Consider:
- Desktop
- Tablet
- Mobile

Ensure layouts remain usable on small screens.

### 5. Cover interface states

Design appropriate:
- Loading states
- Empty states
- Error states
- Success states

Include keyboard accessibility and clear feedback.

### 6. Work with Figma

When Figma tools are available:
- Inspect existing Figma designs.
- Follow established components and styles.
- Propose improvements based on usability.
- Create or update designs only when supported by the available tools and explicitly requested.

Do not assume Figma integration is always available.

### 7. Review before implementation

Evaluate:
- Usability
- Visual hierarchy
- Consistency
- Accessibility
- Responsive behavior
- Alignment with project requirements

Present design decisions and trade-offs.

Request approval before frontend implementation.

## Expected output

Provide:
1. Brief UI/UX design concept.
2. Required screens and user flows.
3. Suggested design system.
4. Component inventory.
5. Responsive behavior.
6. Loading, empty, and error states.
7. Design review checklist.

## Constraints

- Do not modify backend code.
- Do not change API contracts.
- Do not add unrelated product features.
- Do not implement frontend code unless explicitly approved.
- Avoid unnecessary dependencies.
- Prioritize clarity, usability, and maintainability.
